## 2. 평가 방법과 실행 조건

- 경로: `answer.json의 text` → `mask.js maskText()` → 가린 문장만 `rules.js classify()` → 정답(`칸`, `긴급도`)과 비교. 화면의 '규칙으로 채점'과 같은 경로다.
- 정답 필드 이름은 keywords.json `evaluation.fields`에서 읽는다 (id, text, 칸, 긴급도).
- 완전 일치는 업무 유형과 긴급도가 모두 같을 때만 센다. 분류 실패는 오답으로 센다.

## 5. 사고성 요청 평가 가능 여부

| 구분 | 문장 | 근거 |
|---|---|---|
| 기준으로 사고가 명확함 (5) | T01 (잘못된 시술 후 주의사항 발송), T20 (상담실장 개인 휴대폰 번호 노출), T25 (약 복용량 오류), T26 (광고 계정 정지, 캠페인 중단), T29 (지원자 연락처 외부 공개) | criteria 예시와 직접 일치 |

| 사고 아님 (20) | 나머지. T03·T11·T17의 높음은 마감 근거 | 사고 요건 없음 |

잠정 참고값 (공식 지표 아님): '명확' 5건 중 규칙이 높음으로 판정한 것은 4건, 누락 1건(T25).

정확한 측정을 위한 제안:
1. 사람이 30문장마다 `사고`(true/false)를 붙인다. 검토 필요·판단 불가 5건은 기준(보안 사고 포함 여부, 이미 조치된 오류 처리)을 먼저 정한다.
2. answer.json은 수정하지 않고 별도 파일(예: `data/incident_labels.json`, `{id, 사고}`)로 두거나, 사용자가 승인하면 answer.json에 필드를 추가한다. 앱은 keywords.json `evaluation.incident_flag_fields`의 필드가 모든 문장에 true/false로 있을 때만 계산한다(별도 파일을 쓰려면 STEP 5에서 읽는 코드 추가 필요).
3. 지표: `사고 누락률 = (사고=true 이면서 예측 긴급도 ≠ 높음) / (사고=true 문장 수)`. 규칙, AI 1회, AI 2회를 각각 계산한다.

## 8-2. 사고 라벨 평가 구조 (제안, 미적용)

answer.json은 수정하지 않고 별도 파일로 관리한다. 사고 여부를 긴급도 '높음'에서 추론하지 않으며, 라벨이 없는 문장은 미판정으로 둔다. 사고 누락률은 사람 검토가 끝난 뒤에만 계산한다.

제안 파일: `data/incident_labels.json`

```json
{
  "version": 1,
  "criteria_version": 1,
  "criteria_basis": "criteria.json urgency.decision_steps 1단계 (개인정보 노출, 의료정보 오류, 가격 오류, 광고 중단 등)",
  "scope_decisions": {
    "보안 사고(계정 권한 등) 포함 여부": null,
    "이미 조치된(내린) 오류 포함 여부": null,
    "외부 노출 없는 내부 수치 오류 포함 여부": null
  },
  "labels": [
    { "id": "T01", "incident": null, "type": null, "reviewer": null, "reviewed_at": null, "memo": "" }
  ]
}
```

- `incident`: `true` / `false` / `null`(미판정). `type`: `개인정보 노출` / `의료정보 오류` / `가격 오류` / `광고 중단` / `기타`
- 절차:
  1. `scope_decisions` 3개를 사람이 먼저 정한다.
  2. 사람 1명 이상이 30문장 라벨을 붙인다. 가능하면 2명이 따로 붙이고 다른 것만 협의한다.
  3. 검토자와 날짜를 기록한다.
  4. 30개가 모두 `true`/`false`가 된 뒤에만 지표를 계산한다.
- 지표: `사고 누락률 = (incident=true 이면서 예측 긴급도 ≠ 높음) / (incident=true 문장 수)`. 규칙, AI 1회, AI 2회를 각각 계산한다.
- 현재 앱은 사고 필드를 answer.json에서만 찾으므로, 별도 파일을 읽으려면 STEP 5에서 코드 추가가 필요하다.

## 9. STEP 5 AI 2회 평가 설계 (요약)

- 같은 30문장, 같은 criteria.json, 같은 마스킹. 사람 정답은 AI에 보내지 않는다. 1회·2회는 서로 결과를 공유하지 않고 독립 실행한다.
- 평가 중에는 규칙 대체를 끈다. AI 응답이 없거나 형식이 틀리면 '응답 실패'로 세고 오답 처리한다.
- 지표 (r = 1, 2):
  - `유형정확도_r = 맞힌 수 / 30`, 긴급도·완전 일치도 같은 방식
  - `실패율_r = 실패 수 / 30`
  - `실행 간 일치율 = (1회와 2회의 유형·긴급도가 모두 같은 문장 수) / 30` (유형·긴급도 각각도 계산)
  - `변동폭(지표) = |지표_1 − 지표_2|`
  - `개선폭(지표) = min(지표_1, 지표_2) − 지표_규칙` (보수적으로 낮은 쪽 사용)
- 성공 판정 (제안): 업무 유형과 긴급도 각각 `개선폭 > 0` 이고 `개선폭 > 변동폭`.
- 참고: 규칙과 AI의 문장별 교차표(규칙만 맞음 / AI만 맞음)를 함께 보고한다. 30개·2회로는 통계적 우월성을 확정할 수 없다.
